# Audit UX LSP TIK Global

Tanggal: 30 September 2026. Target: proyek lokal, Beranda (`/`) dan Tentang Kami (`/tentang-kami`). Audiens asumsi: calon peserta sertifikasi, kemudian institusi mitra.

## Ringkasan

Prioritas pertama adalah membuat perjalanan pencarian → pemilihan skema → informasi detail dapat diselesaikan. Saat ini pencarian belum mempunyai aksi dan CTA detail dinonaktifkan. Perbaikan keterbacaan menjadi prioritas berikutnya: tinggi baris paragraf, teks metadata kecil, serta kontras placeholder dan teks sekunder. Penambahan animasi dekoratif bukan kebutuhan utama.

Audit ini tidak mengubah UI. Temuan didasarkan pada kode, HTML yang disajikan server lokal, dan perhitungan warna; belum ada observasi pengguna nyata atau pemeriksaan visual melalui browser.

## Rekomendasi visual dan feedback interaksi

### Tipografi dan tata letak

| Elemen | Mobile | Desktop |
| --- | --- | --- |
| H1 | 36–40px / 1,15 | 48–64px / 1,1 |
| H2 | 28–32px / 1,2 | 36–48px / 1,2 |
| H3 | 20–24px / 1,3 | 24–28px / 1,3 |
| Body | 16–18px / 1,5–1,6 | 18px / 1,6 |
| Metadata | 14px / 1,5 | 14px / 1,5 |
| Kontrol utama | 16px; tinggi target 44–48px | 16px; tinggi target 44–48px |

Angka merupakan titik awal untuk diuji, bukan hasil pengukuran browser. Gunakan skala jarak 8/12/16/24/32/48/64px agar ritme konsisten. Pertahankan biru sebagai identitas dan satu gaya CTA utama. Evaluasi apakah tiga keluarga font pada layout memberi manfaat; satu keluarga font dapat menyederhanakan hierarki dan pemuatan.

Target 44–48px merupakan rekomendasi kenyamanan sentuh. Jangan menyatakan semua kontrol di bawah 44px gagal WCAG AA: [WCAG 2.2 target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) menggunakan 24×24 CSS px dengan pengecualian, termasuk jarak antartarget.

### Respons antarmuka

- Pencarian: tampilkan label tetap; setelah submit, “Mencari skema…” bila perlu, kemudian jumlah hasil. Untuk kosong: “Skema tidak ditemukan. Coba kata kunci lain.” Untuk kegagalan: “Skema belum dapat dimuat. Coba lagi atau hubungi kami.” Gunakan status live yang tidak mengganggu ketika hasil berubah tanpa navigasi.
- Tautan dan tombol aktif: bedakan hover, focus-visible, dan pressed. Fokus yang sudah ada dipertahankan. Tombol belum tersedia harus mempunyai alasan yang terbaca atau dikeluarkan dari UI.
- Keberhasilan navigasi: judul halaman dan status navigasi aktif cukup; tidak perlu toast untuk setiap klik. Toast keberhasilan pengiriman hanya relevan bila fitur pengiriman benar-benar ditambahkan.
- Kontak: pertahankan tautan telepon/email yang nyata; label menjelaskan kanal. Audit tidak mengirim pesan atau membuka panggilan.

### Animasi

Kode tidak menunjukkan kebutuhan animasi dekoratif tambahan. Smooth scroll sudah dibatasi pada `prefers-reduced-motion: no-preference`; pertahankan perilaku ini. Jika feedback gerak dibutuhkan, gunakan transisi opacity/transform sekitar 120–180ms, tanpa menggeser layout, dan nonaktifkan gerak nonesensial saat reduced motion. Hindari reveal yang menyembunyikan informasi sampai pengguna menggulir dan carousel otomatis yang tidak diperlukan.

Rekomendasi fokus, status asinkron, dan motion mengacu pada [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). Penerapan harus tetap disesuaikan dengan bahasa Indonesia dan fungsi yang benar-benar tersedia.

## Yang sudah baik

- Bahasa dokumen `id`, satu H1 per halaman, landmark dan label navigasi tersedia.
- Skip link, outline focus-visible global, dan focus-within untuk pencarian sudah ada. Input outline-none tidak berdiri sendiri tanpa pengganti fokus.
- Quick links Tentang Kami memperpendek perjalanan menuju visi, struktur, dan lisensi.
- Bagan mempunyai tombol zoom, status persentase aria-live, area scroll yang dapat difokuskan, dan alternatif daftar.
- Gambar komponen memiliki dimensi; gambar dekoratif umumnya memakai alt kosong. Video menggunakan controls dan preload metadata.
- Empty state struktur dan lisensi sudah tersedia. Ini tidak berarti seluruh respons data kosong dan error telah diuji.

## Pengujian visual yang masih harus dilakukan

| Skenario | Kriteria penerimaan |
| --- | --- |
| Kedua halaman pada 375, 768, 1440px | Tidak ada teks/kontrol terpotong atau horizontal scroll halaman yang tak disengaja; area scroll bagan boleh tetap lokal. |
| Browser zoom 200% | Informasi dan kontrol tetap dapat dibaca/diakses; header, kartu, kontak, dan quick links tidak menutup isi. |
| Tab, Shift+Tab, Enter, Space | Urutan logis, fokus terlihat, skip link bekerja, tidak ada keyboard trap, kontrol native memakai tombol yang sesuai. |
| Pencarian sesudah implementasi | Kedua input menghasilkan hasil konsisten; query kosong, tidak cocok, jaringan lambat dan gagal punya respons jelas. |
| Navigasi dan kontak | Skema, mitra, kontak, visi, struktur, lisensi menuju tujuan sesuai; panggilan/email tidak perlu dikirim untuk pengujian. |
| Bagan | Zoom, Sesuaikan, scroll keyboard, dan daftar dapat dipakai; nama panjang terbaca dan posisi pandang tidak mengejutkan. |
| Reduced motion | Scroll langsung dan gerak nonesensial dinonaktifkan; fungsi tetap tersedia. |
| API lambat/gagal/kosong | Konten penting tidak diam-diam diganti data contoh yang menyesatkan; pesan dan jalur pemulihan sesuai. Uji lewat lingkungan terkontrol. |

## Rencana feedback pengguna nyata

Rekrut awal lima calon peserta dengan campuran pengguna ponsel/desktop dan pengalaman sertifikasi; tambah dua wakil institusi untuk kebutuhan mitra bila relevan. Ini studi kualitatif eksploratif, bukan sampel statistik. Jangan menggunakan testimoni pemasaran sebagai pengganti observasi tugas.

| Tugas tanpa petunjuk lokasi | Hal yang dicatat |
| --- | --- |
| “Cari sertifikasi yang sesuai untuk pekerjaan programmer pemula.” | Pilihan jalur pertama, penggunaan pencarian, titik berhenti, berhasil/tidak tanpa bantuan. |
| “Cari informasi biaya, kompetensi, dan cara melanjutkan proses.” | Informasi yang ditemukan, informasi yang kurang, ekspektasi terhadap Detail. |
| “Cari bukti yang membuat Anda yakin pada lembaga ini.” | Lisensi/testimoni yang dibuka, alasan percaya atau ragu; tidak mengasumsikan kepercayaan meningkat. |
| “Temukan kanal untuk bertanya tentang sertifikasi.” | Waktu menuju kontak dan kejelasan kanal; tidak perlu benar-benar mengirim. |
| “Temukan jabatan tertentu dalam struktur organisasi.” | Pilihan bagan/daftar, kebutuhan zoom, kesulitan membaca. |

Sesudah setiap tugas: “Seberapa mudah tugas ini, 1–7?”, “Apa yang Anda harapkan setelah menekan kontrol tadi?”, dan “Bagian mana yang membingungkan?”. Sesudah sesi: “Informasi apa yang masih kurang sebelum Anda melanjutkan?” serta “Bagaimana kenyamanan ukuran teks dan gerak halaman?”. Hindari pertanyaan mengarahkan seperti “Apakah font ini terlalu kecil?”.

Ledger feedback: kode peserta anonim, perangkat, tugas, hasil tanpa/dengan bantuan, waktu, kutipan persis dengan izin, lokasi hambatan, tingkat keparahan, dan rekomendasi. Pisahkan kutipan, pengamatan, dan interpretasi. Bandingkan hasil baseline dan sesudah perbaikan; jangan mengarang angka konversi atau menjanjikan kenaikan persentase tanpa data.

## Urutan tindak lanjut

1. Pulihkan alur utama: pencarian, katalog nyata, detail, dan CTA; hapus kesan fitur tersedia untuk kontrol yang belum berfungsi.
2. Perbaiki kontras, line-height, metadata, dan keterbacaan lisensi. Validasi pada ketiga viewport dan zoom 200%.
3. Validasi data publik, konsistensi jumlah skema, dan bukti kredibilitas.
4. Uji pengguna, lalu putuskan penyederhanaan header, spacing, dan bagan berdasarkan hambatan yang teramati. Animasi menjadi penyempurnaan terakhir.

## Metode kontras

Rasio dihitung dari nilai hex CSS menggunakan luminansi relatif sRGB dan `(Llebih terang + 0,05)/(Llebih gelap + 0,05)`, bukan estimasi visual. Hasil: putih/action 3,631; placeholder/putih 1,879; muted/putih 4,871; muted/section 4,387; putih/brand 6,086; muted/background 4,522. Pembulatan hanya untuk penyajian.

[WCAG contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) menetapkan 4,5:1 untuk teks normal dan 3:1 untuk teks besar; komponen tidak aktif dikecualikan. Pemeriksaan ini tidak menyatakan kepatuhan WCAG keseluruhan dan belum memperhitungkan latar gambar atau computed style aktual.
